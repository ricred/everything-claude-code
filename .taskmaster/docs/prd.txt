# OpenCode Migration PRD for everything-claude-code

## Context
The everything-claude-code repository is a battle-tested collection of Claude Code configurations developed over 10+ months of intensive daily use. This PRD defines a migration plan to adapt the repository for compatibility with OpenCode.ai (anomalyco/opencode), an open-source AI coding agent with 90K GitHub stars and sophisticated agent architecture.

The primary challenge is that OpenCode has a fundamentally different agent architecture than Claude Code. While both support multi-agent workflows, OpenCode's system is more limited in orchestration capabilities but offers advantages like multi-model support, privacy-first design, and cross-platform compatibility.

## User Experience

### User Personas

1. **Claude Code Power User:** Existing users of everything-claude-code who want to switch to OpenCode
   - Experienced with agent orchestration workflows
   - Relies on sequential/parallel agent chains
   - Values automation and sophisticated patterns

2. **New OpenCode User:** Developers adopting OpenCode who want access to this repository's expertise
   - Unfamiliar with Claude Code's ecosystem
   - Values simplicity and privacy-first design
   - May need guidance on agent workflows

3. **Hybrid User:** Developer using both Claude Code and OpenCode
   - Uses Claude Code for complex orchestration
   - Uses OpenCode for daily development tasks
   - Needs compatibility across both platforms

### Key User Flows

**Migration Flow:**
1. User installs OpenCode and configures model providers
2. User clones migrated repository to `~/.config/opencode/`
3. OpenCode automatically discovers agents and skills from configured paths
4. User starts OpenCode and can access all converted agents/skills
5. User invokes agents via @mentioning or primary agent switching

**Daily Usage Flow (OpenCode-native):**
1. User starts OpenCode TUI or desktop app
2. User selects Build or Plan primary agent
3. User invokes subagent via @mention (e.g., @general)
4. Agent completes task with appropriate tool permissions
5. User can switch between parent/child sessions

**Workaround Flow (for Claude Code patterns):**
1. User manually starts multiple OpenCode sessions
2. User coordinates parallel work across sessions
3. User manually passes context between sessions
4. User aggregates results from multiple sessions

### UI/UX Considerations

- **Agent Discovery:** OpenCode should auto-discover agents/skills from standard paths
- **Permission Clarity:** Users need clear understanding of which agent can do what
- **Multi-session Navigation:** OpenCode's session navigation should be intuitive for parallel workflows
- **Error Messages:** Clear guidance when features are incompatible or require workarounds
- **Documentation:** In-app help for discovering available agents and skills

## Technical Architecture

### System Components

1. **OpenCode Agent System**
   - Primary agents: Build (full access), Plan (restricted)
   - Subagents: General (multi-step tasks), Explore (read-only codebase exploration)
   - Configuration via JSON (`opencode.json`) and Markdown (`~/.config/opencode/agents/*.md`)

2. **Agent Skills System**
   - SKILL.md format for skill definitions
   - Discovery paths: global (`~/.config/opencode/skills/`) and project (`.opencode/skills/`)
   - Activated via agent context or user requests

3. **Permission System**
   - Per-agent tool permissions (write, edit, bash, etc.)
   - Permission levels: allow, ask, deny
   - Glob patterns for fine-grained bash command control
   - Task permissions for controlling which subagents an agent can invoke

4. **Multi-Session Architecture**
   - Parent sessions with child sessions created by subagents
   - Session cycling via keybinds (<Leader>+Right, <Leader>+Left)
   - Independent session contexts while maintaining relationship

5. **Configuration Layers**
   - Global config: `~/.config/opencode/opencode.json`
   - Project config: `.opencode/opencode.json`
   - Environment variable overrides
   - Priority: project > global > defaults

### Data Models

1. **Agent Configuration Model**
   - Mode: primary, subagent, or all
   - Tools: object with boolean flags for each tool
   - Permissions: object mapping tools to allow/ask/deny
   - Model: provider/model-id string
   - Temperature, maxSteps, hidden, taskPermission settings

2. **Skill Definition Model**
   - Frontmatter with metadata (description, mode, tools, model, temperature)
   - Markdown content for skill instructions
   - Compatibility with Agent Skills open standard

3. **Permission Model**
   - Hierarchical: global > agent-specific
   - Glob pattern matching for flexible rules
   - Last matching rule wins principle

### APIs and Integrations

1. **OpenCode Internal APIs**
   - Agent invocation via Task tool
   - Session management APIs
   - Configuration loading and validation
   - Permission checking and enforcement

2. **Model Provider Integration**
   - 75+ providers (Anthropic, OpenAI, Google, local models, etc.)
   - Provider-specific parameters (reasoningEffort, textVerbosity)
   - OpenCode Zen for optimized models

3. **External Tool Integration**
   - MCP (Model Context Protocol) servers
   - LSP (Language Server Protocol) integration
   - Custom tools via OpenCode's plugin system

### Infrastructure Requirements

1. **File System**
   - `~/.config/opencode/` - Global agents, skills, config
   - `.opencode/` - Project-specific agents, skills, config
   - `.opencode/logs/` - Session logs
   - Standard XDG directory support

2. **Cross-Platform Support**
   - macOS, Linux, Windows (PowerShell and WSL)
   - Desktop apps (beta)
   - Terminals (TUI)

3. **Version Control**
   - Git integration for attribution
   - Session sharing via links
   - AGENTS.md initialization for project context

## Risks and Mitigations

### Technical Challenges

**Risk 1: OpenCode's Limited Orchestration**
- **Issue:** No native support for sequential/parallel agent chains
- **Impact:** Core value proposition (orchestrated workflows) lost
- **Mitigation:** Document manual multi-session coordination patterns
- **Mitigation:** Create guide for parallel session management
- **Mitigation:** Prioritize single-agent workflows where possible

**Risk 2: Agent Permission Differences**
- **Issue:** OpenCode's permission system is different from Claude Code
- **Impact:** Some agent capabilities cannot be exactly replicated
- **Mitigation:** Map Claude Code's scoped tools to nearest OpenCode equivalent
- **Mitigation:** Document permission trade-offs clearly

**Risk 3: Missing Hook System**
- **Issue:** No event-driven automation for memory/compaction
- **Impact:** Loss of automated workflows
- **Mitigation:** Create manual workflows for critical tasks
- **Mitigation:** Document OpenCode's native session management features

**Risk 4: Skills Format Differences**
- **Issue:** Subtle differences between Claude Code and OpenCode formats
- **Impact:** Some skills may not work identically
- **Mitigation:** Test each skill thoroughly
- **Mitigation:** Document format variations and workarounds

**Risk 5: Command System Differences**
- **Issue:** OpenCode lacks native slash command system
- **Impact:** Commands become prompts rather than quick invocations
- **Mitigation:** Create custom commands via OpenCode's configuration
- **Mitigation:** Document prompt patterns for command-like workflows

## Appendix

### Research Findings

**OpenCode Agent System Capabilities:**
- Supports two agent types: primary agents and subagents
- Two built-in primary agents: Build (full access), Plan (restricted)
- Two built-in subagents: General (multi-step), Explore (read-only)
- Agent configuration via JSON or Markdown files
- Tool permission system with allow/ask/deny levels
- Task permissions for subagent invocation control
- Multi-session support with parent/child relationships
- Session cycling via keybinds for navigation

**Claude Code vs OpenCode Comparison:**
- Claude Code: Native orchestration, 12+ custom agents, hooks system, rules system
- OpenCode: Limited orchestration, 2+ built-in subagents, multi-session support
- Claude Code: Agent-specific tools, slash commands, contexts system
- OpenCode: Permission-based tools, @mentioning, session management

**Feature Compatibility Matrix:**
| Feature | Claude Code | OpenCode | Migration Notes |
|----------|-------------|----------|----------------|
| Agent Definition | .md files | .md and JSON | Compatible format |
| Agent Orchestration | Native | Limited | Manual workaround needed |
| Parallel Agents | Built-in | Multi-session | Sessions need coordination |
| Tool Permissions | Per-agent | Permission system | Mapping required |
| Subagent Invocation | Task tool | @mentioning | Different mechanism |
| Skills | Custom format | Agent Skills | SKILL.md compatible |
| Slash Commands | Native | Not native | Custom commands or prompts |
| Hooks | Event-driven | Not available | Manual workflows |
| Rules | Always-follow | Agent prompts | Different mechanism |
| Contexts | Dynamic injection | AGENTS.md | Adaptation needed |
| Memory | Hooks/session | Multi-session | Different persistence |
| Compaction | Automatic | Manual | User-initiated |

### Technical Specifications

**Agent Configuration JSON Schema:**
```json
{
  "agent": {
    "<agent-name>": {
      "description": "string (required)",
      "mode": "primary|subagent|all",
      "model": "provider/model-id",
      "prompt": "{file:./prompts/agent.txt} or direct string",
      "tools": {
        "write": boolean,
        "edit": boolean,
        "bash": boolean,
        "grep": boolean,
        "ls": boolean,
        "view": boolean,
        "webfetch": boolean
      },
      "permission": {
        "edit": "allow|ask|deny",
        "bash": {
          "glob-pattern": "allow|ask|deny"
        }
      },
      "maxSteps": number,
      "temperature": number,
      "hidden": boolean,
      "taskPermission": {
        "glob-pattern": "allow|ask|deny"
      }
    }
  }
}
```

**Agent Configuration Markdown Schema:**
```markdown
---
description: Brief description
mode: primary|subagent|all
model: provider/model-id
prompt: Direct instructions or {file:./prompts/agent.txt}
temperature: number
maxSteps: number
tools:
  write: boolean
  edit: boolean
  bash: boolean
permission:
  edit: allow|ask|deny
  bash: allow|ask|deny
hidden: boolean
---
Agent instructions here...
```

**Skill Definition Schema (SKILL.md):**
```markdown
---
description: Skill description
mode: subagent
model: provider/model-id
temperature: number
tools:
  write: boolean
  edit: boolean
  bash: boolean
---

Skill instructions here...
```

**OpenCode Configuration Schema:**
```json
{
  "$schema": "https://opencode.ai/config.json",
  "agent": {
    "<agent-name>": { /* agent config */ }
  },
  "options": {
    "skills_paths": ["~/.config/opencode/skills", ".opencode/skills"],
    "initialize_as": "AGENTS.md"
  },
  "permission": {
    "edit": "allow|ask|deny",
    "bash": "allow|ask|deny"
  }
}
```

**Directory Structure for Migration:**
```
~/.config/opencode/
├── agents/              # Converted agents (markdown format)
├── skills/              # Converted skills (SKILL.md format)
├── opencode.json        # Main configuration
└── AGENTS.md           # Optional: project context (equivalent to CLAUDE.md)

.opencode/              # Project-specific (overrides global)
├── agents/              # Project agents
├── skills/              # Project skills
└── opencode.json        # Project configuration

project/
├── agents/              # Original Claude Code agents (keep for reference)
├── skills/              # Original Claude Code skills (keep for reference)
├── commands/            # Original commands (adapt to prompts)
├── rules/               # Original rules (adapt to agent prompts)
├── contexts/            # Original contexts (adapt to AGENTS.md)
├── hooks/               # Original hooks (document workarounds)
├── scripts/             # Scripts (adapt or replace)
└── MIGRATION_GUIDE.md # New: OpenCode migration guide
```
